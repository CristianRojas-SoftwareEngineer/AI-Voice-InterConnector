<!-- <overview> -->
Reusable task command for the complete published-release Windows E2E as a final user. The PowerShell executor at `scripts/test-windows-e2e-as-final-user.ps1` is the sole implementation of the `0a→0b→1–7` workflow; this skill defines its contract and the human approval gates. It validates the published bundle, persistent Windows PATH, model/runtime integration, daemon and available audio hardware. Deterministic parser, error-code and isolation contracts remain Rust-test coverage. Leave the installed application, models and generated user data provisioned after a successful run. The app-owned roots are defined in `crates/avi-shared/src/paths.rs`; cleanup, uninstall, doctor repair and `cargo xtask clean` have distinct scopes.
<!-- </overview> -->

## When it applies

- The user asks for a Windows E2E, release validation as a final user, or a full install-and-use walkthrough.
- Pre-release gate before publishing `vX.Y.Z` or after a release pipeline smoke test.
- Regression after changes to `packaging/bootstrap/install.ps1`, lifecycle install/cleanup, stores, daemon or TTS dispatch.

## Preconditions

- **Host:** Windows 10+ x64 with PowerShell 5.1+ on the development machine. The installation is per-user and does not require UAC.
- **Cost:** approximately 5.86 GB for the six pinned models (`qwen3-tts-0.6b`, `qwen3-tts-0.6b-base`, `parakeet-tdt-v3`, both Opus-MT directions and `dpdfnet8`; see `MODEL_REVISIONS` and `ModelPin::approx_bytes` in `crates/avi-shared/src/paths.rs`). `dpdfnet8` is startup-optional but required by the complete setup/doctor criterion. The Base model is always provisioned by `setup`; there is no clone-model flag. Windows snapshots use hardlinks to avoid duplicate model storage.
- **State:** the system under test is the installed bundle and its owned roots (`%LOCALAPPDATA%\Programs\ai-voice-interconnector`, `%LOCALAPPDATA%\ai-voice-interconnector\data`, `%LOCALAPPDATA%\ai-voice-interconnector\cache\models`, scratch and staging as resolved by `crates/avi-shared/src/paths.rs`). Every invocation inspects first. Never delete the shared Hugging Face cache except app-owned pinned repos explicitly selected by the official cleanup plan. Preserve the installed application, models and generated data after the run.
- **Contract:** CLI envelope `schema_version="5"` (`CLI_SCHEMA_VERSION`) and daemon protocol `schema_version="5"` (`DAEMON_SCHEMA_VERSION`) are independent contracts in `crates/avi-core/src/json_emitter.rs`. WAV output is PCM16 mono at 24 kHz. When Parakeet is provisioned, short-text TTS must meet WER ≤0.25. Code signing/SmartScreen remains deferred in `docs/GOAL.md`.

## Roles and execution contract

- The human reviews each cleanup and uninstall target list separately, including measured sizes, preserved roots and expected model redownload; every inventoried residue must be covered by an official plan or the run is `BLOCKED`. Fresh explicit consent is bound to the exact normalized paths and effects. Consent for cleanup, uninstall, model provisioning and any auxiliary download is separate; plan approval, earlier consent and `-Yes` do not authorize destructive operations. Setup repair with `--force-update --yes` requires another fresh approval after presenting its scope and download estimate.
- The script is the only workflow executor. It creates a unique evidence directory outside any target roots, invokes the CLI only by full path, records process metadata and raw streams, parses command payloads, asserts outcomes and stops on the first required `FAIL` or `BLOCKED`. It never retries, repairs, purges at the end or rolls back partial product changes.
- The agent checks prerequisites and script validity, reports exact dry-runs to the human, supplies explicit interactive answers only after consent, and reports recorded results without substituting commands or interpreting a failure as success.

The persistent user PATH in `HKCU\Environment` differs from the inherited process PATH. For `where.exe` and doctor checks, the executor launches a child with PATH rebuilt from persisted Machine and User values without mutating the parent. It drains both process streams and bounds every wait. On timeout, it terminates only the process/PID tree created by that invocation where the plan explicitly permits; it never kills by image name. CLI output is logged with secrets redacted; evidence must not contain credentials or tokens.

## Invocation and results

From the repository root, use the current PowerShell host and do not pass a global consent switch:

```powershell
& .\.claude\skills\test-windows-e2e-as-final-user\scripts\test-windows-e2e-as-final-user.ps1
```

The script validates Windows x64 and PowerShell 5.1+, checks the source version against Cargo, fixture and latest tag, resolves the published release, and refuses to run if it or required inputs are missing or invalid. Each run records a preflight result and one terminal result per executed phase; phases not reached after fail-fast remain explicitly unexecuted in the overall failure report. It stops as `BLOCKED` before any action lacking its required fresh, scoped consent; implementation and AST validation must finish before a real run. Each step/subcase follows `PENDING → RUNNING → PASS | FAIL | SKIP | BLOCKED`. `SKIP` is allowed only for an optional capability whose absence was observed (for example, an audio device); operational errors in a provisioned feature are `FAIL`. A required failure/block stops subsequent actions and makes the overall result non-success. Evidence includes a unique run directory, command arguments, start/end timestamps, PID, timeout, stdout/stderr, exit code, parsed JSON/JSONL and artifact paths. Every executed command and optional subcase has its own structured result with command, exit code, payload/evidence paths and a reason for `SKIP` or `BLOCKED`; phases after fail-fast are recorded as unexecuted, and no required subcase may remain pending at successful completion. Preserve evidence and any partial state on failure.

## Required coverage

The executor must implement this complete ordered workflow and must not delegate execution to manual steps:

- **0a — initial inventory and cleanup gate:** inspect the receipt, ownership, exact roots, sizes, persisted PATH, staging, scratch, failure logs and official cleanup/uninstall dry-runs. Missing binary plus any residue is `BLOCKED`. Show the exact destinations from each dry-run separately, preserved roots returned by the official contract, their sizes and expected model redownload, then request fresh interactive consent bound to exactly those normalized targets and effects. If cleanup does not expose preserved roots, report `BLOCKED` rather than infer or omit them. Any residue not represented by an official plan is `BLOCKED`. If consent is absent/denied, report `BLOCKED` and perform no destructive command. After consent only, stop and verify the daemon; immediately before each official destructive operation, rerun its dry-run and require exact target-set equality with the approved set before invoking `--yes`. Verify actual absence of every owned destination, including scheduled removals, failure logs, PATH and child `where.exe`; `not_installed` is not evidence that a still-present owned root was removed. Never manually delete roots or shared Hugging Face cache.
- **0b — release resolution:** compare source version, latest tag and `tests/golden/cli_version.json`; verify the seven expected stable GitHub Release assets and parse its `SHA256SUMS.txt` to record the expected hash for the Windows ZIP. Run `cargo test --test cli_golden version_matches_fixture` against the current source and record command, features, result and pass/fail/ignored counts separately from the published-release E2E; this gate is not evidence about the published binary.
- **1 — published bootstrap:** invoke the published `install.ps1` with `AVI_NO_SETUP=1`; bind the verified ZIP to the same versioned release asset and compare its observed SHA256 to the 0b value. A generic bootstrap success message alone is insufficient unless it exposes evidence tying the checksum to that exact asset/hash. If the bootstrap does not expose the verifiable value, require an independently calculated checksum of that same release ZIP under a separate fresh download consent before accepting installation; otherwise `BLOCKED`. Validate the receipt, compare `version --json` and CLI schema with the source/fixture, assert exactly one persistent HKCU PATH entry, then resolve `where.exe` in a child with persisted PATH.
- **2 — setup:** record the expected pre-setup doctor failure and present the missing-model list plus its estimated bytes; require fresh consent before any model download. Then run `setup --json` with fresh stdout/stderr and a 1,200,000 ms timeout. Require exit 0, completed status, all six exact pinned revisions and required non-empty weights/files, clean pending artifacts, passing doctor and a single child that runs both `where.exe` and doctor with persisted Machine+User PATH. `devices --json` must exit 0 and parse with the current schema; preserve its device/error payload. An enumeration error is `FAIL`, not proof that optional hardware is absent. Timeout stops only the invocation-owned process tree, preserves evidence and state, and never retries. `--force-update --yes` is never an automatic repair.
- **3 — daemon:** verify initially stopped; start and confirm exit 0 with status `started` and `daemon: running`; because the initial state is verified stopped, `already_running` is not accepted as a successful start in this flow. Poll `daemon status` and `/health` until `warm: "warm"`; retain the returned PID/identity, verify it remains the same process before owned stops, and use fresh stdout/stderr logs. The start CLI has its own bounded deadline; it launches a detached daemon, so the short timeout bounds command completion rather than daemon lifetime. Use the installed engine/vendor; never rely on CWD or `QWEN3_TTS_BIN`.
- **4 — voices:** verify factory voices; clone `mi_voz` direct and `mi_voz_daemon`; assert the CLI-reported qvoice exists and is non-empty (over 1 MB for the direct sample) and that no reference WAV was copied; test duplicate conflict exit 6 and explicit `--force`; clone with denoise. `devices --json` enumerates outputs and is not evidence of input hardware. Attempt microphone cloning only when capture availability is independently observable; otherwise record `SKIP` with the missing capability evidence, without treating an enumeration error as absence or attempting capture. Preserve designated voices.
- **5 — synthesis and WER:** cover Auto with factory and cloned voices, ForceDaemon with factory and cloned voices, and ForceDirect with cloned voice plus factory same-language and cross-language text, including a valid temperature override; verify successful payloads and every WAV as PCM16 mono 24 kHz. Confirm the synthesized store contains the labels from every required matrix cell. Save the cloned short sample through ForceDaemon before its WER check, using the same reference text `"Hola mundo"` as the factory sample. Require audible confirmation for `say`; JSON alone is insufficient. Stop and verify daemon before direct cases; this step ends stopped. If Parakeet is provisioned (`native-stt` is enabled and the pinned model is present), transcribe both short samples and compute WER with the normalization and Levenshtein behavior in `tests/cli_golden.rs`; require ≤0.25 and record both transcripts and scores. If the feature/model is absent before the WER cases begin, mark only those optional WER cases `SKIP`; once a transcription command is attempted, its operational error is `FAIL`.
- **6 — store, STT, translation, dub and denoise:** exercise speech list/filter/play/remove and removal of one disposable voice plus its owned speech namespace, asserting operation results and post-removal absence; audio STT with schema and source-language checks plus optional microphone STT only when capture capability is independently observed; otherwise `SKIP` only the microphone case with the missing capability evidence; real es→en daemon and en→es direct translations plus passthrough; cross-language daemon and direct dub when output hardware is available; denoise-enabled transcribe/dub; bundled FFmpeg and both denoise presets with valid JSONL summary, zero failures and non-empty listed outputs. Independently observe output capability before `say`, `play` or either dub; if absent, skip only those dependent cases before invoking them. Enumeration errors are `FAIL`, not absence. Verify DPDFNet is provisioned before denoise-enabled STT/dub. Explicitly start and verify warm before every daemon group after a stop, and verify stopped before direct groups. Do not run `--daemon` while stopped.
- **7 — final state:** verify persisted PATH has one entry; `where.exe`, `version --json` and doctor pass in the same persisted-PATH child; doctor receipt, installed version and executable agree; the doctor’s model root is `<receipt.roots.cache_dir>\models`, all six exact pinned models are provisioned, all pending arrays and transaction journal are clean, and report measured data/model-root sizes. Require every designated qvoice/WAV and every listed output from both denoise presets to remain present and non-empty. Report final daemon/warm state. Never clean or uninstall at the end.

The two schema values are independent and currently both `5`: CLI `CLI_SCHEMA_VERSION` and daemon `DAEMON_SCHEMA_VERSION` in `crates/avi-core/src/json_emitter.rs`. Model pins and relocatable roots are defined in `crates/avi-shared/src/paths.rs`. The WER reference implementation is in `tests/cli_golden.rs`.

## Safety and stop conditions

- Approval of this plan authorizes neither purge nor a real E2E run. During implementation, validate parsing, gates and failures only in isolated data/environment or controlled mocks; do not download models, invoke the published bootstrap, purge user state or run the real E2E.
- If the executor is absent, empty or invalid, report `BLOCKED`; never perform the workflow manually as fallback. The script must validate its own syntax before any product command.
- No destructive operation without a fresh, exact-path interactive approval after the executor displays actual dry-run targets and sizes. No consent is reusable. `setup --force-update --yes` has an additional independent gate. Do not mutate the parent PATH, infer ownership from conventional paths, erase foreign cache, use `taskkill /IM`, or automatically undo partial changes.
- Do not modify `docs/`, `Cargo` or `.circleci`. The executor runs the targeted source gate separately from the published-release E2E and reports exact command/features and pass/fail/ignored counts. During implementation, do not execute bootstrap, setup, destructive commands, model downloads or the real E2E. Do not present a historical release gate as current.
- Report `PASS/FAIL/SKIP/BLOCKED` for every step/subcase with command, exit code, payload and evidence path. A user-denied or unavailable consent gate is `BLOCKED`, not `FAIL` or `PASS`. Never declare success if a required check failed or remained blocked.
